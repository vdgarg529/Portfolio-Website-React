
# Exploratory Data Analysis (EDA) with Python

Exploratory Data Analysis is the process of examining a dataset visually and statistically before applying formal statistical models or machine-learning algorithms.

EDA helps answer questions such as:

```text
What variables are present?

What does each variable represent?

How are the values distributed?

Are there missing or invalid values?

Are there unusual observations?

How do different groups behave?

Which variables appear related?

Are there trends over time?

Which hypotheses should be investigated further?
```

EDA is not only about creating charts. It combines:

```text
Data inspection
Descriptive statistics
Visualization
Distribution analysis
Correlation analysis
Group comparison
Outlier investigation
Pattern discovery
Hypothesis generation
```

Typical EDA workflow:

```text
Prepared dataset
      ↓
Understand structure
      ↓
Univariate analysis
      ↓
Bivariate analysis
      ↓
Multivariate analysis
      ↓
Distribution analysis
      ↓
Correlation and association analysis
      ↓
Outlier and anomaly analysis
      ↓
Time-based analysis
      ↓
Hypothesis generation
      ↓
Documented findings
```

## 16. Choosing the Number of Bins

Too few bins:

```text
Can hide important patterns.
```

Too many bins:

```text
Can make the plot noisy.
```

Specify bins manually:

```python
sns.histplot(
    data=df,
    x="sales",
    bins=20
)
```

Use automatic bin selection:

```python
plt.hist(
    df["sales"].dropna(),
    bins="auto"
)

plt.show()
```

Common strategies:

```text
"auto"
"sturges"
"fd"
"sqrt"
```

The Freedman-Diaconis strategy:

```python
plt.hist(
    df["sales"].dropna(),
    bins="fd"
)
```

is useful for skewed data and larger samples.

## 23. Quantile-Quantile Plot

```python

    df["sales"].dropna(),

)

    "Q-Q Plot for Sales"

```

### Interpretation

```text

Points curve away from the line:
```

### When to use

Use a Q-Q plot when checking whether a numerical variable approximately follows a theoretical distribution.

## 24. Skewness

```python

```

Approximate interpretation:

```text
Between -0.5 and 0.5:
Relatively symmetric.

Between 0.5 and 1:
Moderately right-skewed.

Greater than 1:
Strongly right-skewed.

Between -1 and -0.5:
Moderately left-skewed.

Less than -1:
Strongly left-skewed.
```

These are practical guidelines rather than strict rules.

## 26. Normality Tests

Shapiro-Wilk test:

```python
sample = (
    df["sales"]
      .dropna()
)

if len(sample) > 5000:
    sample = sample.sample(
        5000,
        random_state=42
    )

statistic, p_value = stats.shapiro(
    sample
)

print(
    "Statistic:",
    statistic
)

print(
    "P-value:",
    p_value
)
```

D'Agostino's test:

```python
statistic, p_value = stats.normaltest(
    df["sales"].dropna()
)
```

### Important caution

With very large datasets, normality tests may reject normality for minor deviations.

Use them together with:

```text
Histogram
Q-Q plot
Skewness
Kurtosis
Domain knowledge
```

Do not decide normality from a p-value alone.

## 33. Pareto Analysis

A Pareto chart combines descending category values with cumulative percentage.

```python
pareto = (
    df.groupby("category")["sales"]
      .sum()
      .sort_values(
          ascending=False
      )
      .reset_index()
)

pareto["cumulative_percent"] = (
    pareto["sales"]
      .cumsum()
    / pareto["sales"].sum()
    * 100
)
```

Plot:

```python
fig, ax1 = plt.subplots(
    figsize=(10, 5)
)

ax1.bar(
    pareto["category"],
    pareto["sales"]
)

ax1.set_ylabel(
    "Sales"
)

ax1.tick_params(
    axis="x",
    rotation=45
)

ax2 = ax1.twinx()

ax2.plot(
    pareto["category"],
    pareto["cumulative_percent"],
    marker="o"
)

ax2.set_ylabel(
    "Cumulative Percentage"
)

ax2.axhline(
    80,
    linestyle="--"
)

plt.tight_layout()
plt.show()
```

### When to use

Use Pareto analysis to identify:

```text
Categories contributing most revenue
Products creating most defects
Customers producing most sales
Sources causing most incidents
```

# Part G: Correlation Analysis

## 42. What Is Correlation?

Correlation measures the direction and strength of association between variables.

Typical range:

```text
-1 to +1
```

Interpretation:

```text
+1:
Perfect positive association.

0:
No measured association under the selected method.

-1:
Perfect negative association.
```

Correlation describes association, not causation.

---

## 49. Find Strong Correlations Programmatically

```python
correlation_pairs = (
    correlation_matrix
      .where(
          np.triu(
              np.ones(
                  correlation_matrix.shape
              ),
              k=1
          ).astype(bool)
      )
      .stack()
      .sort_values(
          key=abs,
          ascending=False
      )
)

print(
    correlation_pairs.head(10)
)
```

Filter above a threshold:

```python

    correlation_pairs[
        correlation_pairs.abs() >= 0.70

)
```

The threshold should depend on the problem rather than being treated as a universal rule.

## 50. Correlation Strength Guidelines

A rough interpretation:

```text
0.00 to 0.19:
Very weak.

0.20 to 0.39:
Weak.

0.40 to 0.59:
Moderate.

0.60 to 0.79:
Strong.

0.80 to 1.00:
Very strong.
```

Apply the same interpretation to absolute negative values.

These ranges are context-dependent.

A correlation of `0.30` may be important in social science but weak in a controlled physical system.

## 70. Cramér's V

Cramér's V measures the strength of association between categorical variables.

```python
def cramers_v(
    first,
    second
):
    table = pd.crosstab(
        first,
        second
    )

    chi_square = (
        stats.chi2_contingency(
            table
        )[0]
    )

    total = table.to_numpy().sum()

    rows, columns = table.shape

    denominator = (
        total
        * min(
            rows - 1,
            columns - 1
        )
    )

    if denominator == 0:
        return np.nan

    return np.sqrt(
        chi_square
        / denominator
    )
```

Usage:

```python
association = cramers_v(
    df["subscription_type"],
    df["churn"]
)

print(association)
```

Typical range:

```text
0:
No association.

1:
Perfect association.
```

Interpretation depends on table size and domain context.

## 77. What Is Multicollinearity?

Multicollinearity occurs when predictor variables contain strongly overlapping information.

Possible consequences:

```text
Unstable linear-model coefficients
Large coefficient standard errors
Difficult interpretation
Sensitivity to small data changes
```

Correlation heatmaps provide an initial check but may not detect all multicollinearity.

```text
Interactive exploration becomes unresponsive
```

Calculate final summary statistics using the full dataset whenever practical.

# Part Q: Hypothesis Generation

## 108. What Is an EDA Hypothesis?

An EDA hypothesis is a possible explanation or relationship suggested by the data.

Example observation:

```text
Customers with annual plans appear to churn less.
```

Possible hypothesis:

```text
Annual subscriptions may improve retention.
```

This should later be tested using:

```text
Statistical testing
Controlled experiments
Regression analysis
Additional data
Domain investigation
```

---

## 109. Observation vs Hypothesis vs Conclusion

```text
Observation:
The South region has lower average sales.

Hypothesis:
The South region may have fewer active stores.

Analysis:
Compare store count, customer traffic and product availability.

Conclusion:
Supported only after sufficient evidence is collected.
```

EDA findings should not automatically be presented as causal conclusions.

# Part R: Reusable EDA Functions

## 111. Numerical EDA Function

```python
def numerical_eda(
    df,
    column
):
    series = (
        df[column]
          .dropna()
    )

    summary = pd.Series({
        "count": series.count(),
        "missing": (
            df[column]
              .isna()
              .sum()
        ),
        "mean": series.mean(),
        "median": series.median(),
        "standard_deviation": (
            series.std()
        ),
        "minimum": series.min(),
        "q1": series.quantile(0.25),
        "q3": series.quantile(0.75),
        "maximum": series.max(),
        "skewness": series.skew(),
        "kurtosis": series.kurt()
    })

    fig, axes = plt.subplots(
        1,
        2,
        figsize=(12, 4)
    )

    sns.histplot(
        x=series,
        kde=True,
        ax=axes[0]
    )

    axes[0].set_title(
        f"Distribution of {column}"
    )

    sns.boxplot(
        x=series,
        ax=axes[1]
    )

    axes[1].set_title(
        f"Box Plot of {column}"
    )

    plt.tight_layout()
    plt.show()

    return summary
```

Usage:

```python
sales_summary = numerical_eda(
    df,
    "sales"
)

print(sales_summary)
```

```python
def categorical_eda(
    df,
    column,
    top_n=20
):
    summary = (
        df[column]
          .value_counts(
              dropna=False
          )
          .head(top_n)

    summary["percentage"] = (
        summary["count"]

    plt.figure(
        figsize=(10, 5)
    )

    sns.barplot(
        data=summary,
        x="count",
        y=column
    )

    plt.title(
        f"Top Categories in {column}"
    )

    plt.show()

    return summary
```

## 113. Correlation EDA Function

```python
def correlation_eda(
    df,
    method="pearson"
):
    numeric_data = (
        df.select_dtypes(
            include="number"
        )
    )

    correlation = numeric_data.corr(
        method=method
    )

    mask = np.triu(
        np.ones_like(
            correlation,
            dtype=bool
        )
    )

    plt.figure(
        figsize=(12, 8)
    )

    sns.heatmap(
        correlation,
        mask=mask,
        annot=True,
        fmt=".2f",
        cmap="coolwarm",
        center=0
    )

    plt.title(
        f"{method.title()} Correlation"
    )

    plt.show()

    return correlation
```

# Part U: Common EDA Mistakes

## 123. Creating Charts Without a Question

A chart should answer a question.

Weak approach:

```text
Plot every column because it exists.
```

Better approach:

```text
Question:
Does discount appear related to profit?

Chart:
Scatter plot of discount vs profit.
```

---

## 124. Using the Wrong Chart Type

Examples:

```text
Pie chart for 25 categories:
Difficult to compare.

Line plot for unordered categories:
Implies a sequence that may not exist.

Bar chart for a continuous distribution:
Can hide distribution shape.

Scatter plot for categorical values:
May not communicate frequencies clearly.
```

---

## 125. Ignoring Sample Size

A group with a high average may contain only two observations.

Always report:

```text
Count
Mean or median
Spread
Missing values
```

Example:

```python
df.groupby("region").agg(
    sample_size=(
        "sales",
        "count"
    ),
    average_sales=(
        "sales",
        "mean"
    ),
    median_sales=(
        "sales",
        "median"
    )
)
```

---

## 126. Ignoring Missing Values in Plots

Many plotting functions silently remove missing values.

Always compare:

```python
df["sales"].count()
df["sales"].isna().sum()
```

A chart based on 60% of the records may not represent the full dataset.

---

## 127. Removing Outliers Before Investigating

Outliers may represent:

```text
Errors
Fraud
High-value customers
Rare events
New customer segments
System failures
```

Investigate before removing or capping them.

---

## 128. Interpreting Correlation as Causation

Correlation is useful for hypothesis generation, not causal proof.

Causal claims generally require:

```text
Experimental design
Natural experiments
Causal inference methods
Temporal evidence
Domain reasoning
```

---

## 129. Using Too Many Visual Dimensions

A scatter plot with:

```text
x
y
colour
size
symbol
facet row
facet column
```

can become difficult to understand.

Prefer several clear plots over one overloaded plot.

---

## 130. Ignoring Scale Differences

Example:

```text
Revenue ranges from 1,000 to 1,000,000.
Rating ranges from 1 to 5.
```

Parallel plots, PCA and distance-based methods may require scaling.

---

## 131. Inspecting Only Averages

Two groups can have the same mean but different:

```text
Spread
Skewness
Outliers
Subgroups
Sample sizes
```

Always inspect distributions.

---

## 132. Overusing Normality Tests

Large datasets almost always show statistically detectable deviations from perfect normality.

Use visual inspection and consider whether the selected method actually requires normal data.

---

## 133. Conducting Too Many Tests

Testing many relationships increases the chance of false discoveries.

When running many statistical tests, consider:

```text
Bonferroni correction
Holm correction
False discovery rate
```

EDA hypotheses should ideally be confirmed using separate or new data.

---

## 134. Data Leakage During EDA

Do not use test-set target information to make modeling decisions repeatedly.

Recommended workflow:

```text
Perform broad EDA on training data
Develop preprocessing and models
Use validation data for model choices
Use test data once for final evaluation
```

# Final Concept Summary

Exploratory Data Analysis answers:

```text
What does the dataset contain?

How are individual variables distributed?

How do groups differ?

Which variables appear related?

Are there unusual observations?

Do patterns change over time?

Which questions require further investigation?
```

Univariate analysis examines:

```text
One variable at a time.
```

Bivariate analysis examines:

```text
The relationship between two variables.
```

Multivariate analysis examines:

```text
Patterns involving three or more variables.
```

Data visualization helps:

```text
Reveal patterns that may not be visible in summary tables.
```

Correlation analysis helps:

```text
Measure the direction and strength of relationships.
```

Distribution analysis helps:

```text
Understand central values, spread, skewness, tails and anomalies.
```

Outlier analysis helps:

```text
Identify errors, rare events and unusual combinations.
```

Time-series EDA helps:

```text
Reveal trend, seasonality, volatility and lag relationships.
```

The main purpose of EDA is not to prove conclusions. Its purpose is to understand the dataset, discover meaningful patterns, detect problems and generate well-supported questions for deeper analysis.
